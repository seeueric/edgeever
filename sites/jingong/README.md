# 精工工业建筑系统集团有限公司 · 官网 / Corporate site

中英双语静态站点，无构建步骤、无运行时依赖。整个目录可直接上传到任意静态托管
（Cloudflare Pages、对象存储、nginx）。

- 中文：`/`
- English：`/en/`

> ⚠️ **站内所有文字、性能参数、工程案例与下载资料均为占位样例**，用于确定结构与视觉。
> 对外发布前必须按下方《上线前必改清单》逐项替换。

## 信息架构：制造商站，不是承包商站

站点按**产品目录**组织，而不是按"业务板块"。这是建材制造商官网与工程承包商官网
最根本的区别：

- **承包商站**：导航按能力 + 业绩展开，目标是让业主发起一次项目洽谈。
- **制造商站**：导航按产品族展开 → 每个产品有独立页面，给选型参数、材料规范、
  性能选项和**技术资料下载**。目标是让设计院**在图纸里指定这个系统**。

精工两头都占：围护系统和装配式系统可以产品化供货，钢结构又能做 EPC。所以：

```
产品与系统 (products.html)     ← 四个系统，各有独立产品页
  ├ 钢结构系统    product-steel.html      ★ 模板页，内容最完整
  ├ 装配式建筑系统 product-modular.html
  ├ 金属围护系统   product-envelope.html
  └ 光伏屋面系统   product-bipv.html
服务与支持 (services.html)     ← EPC 总承包 #epc / 检测与运维 #service
工程业绩   (projects.html)
关于精工   (about.html)
新闻中心   (news.html)
联系我们   (contact.html)
```

### 产品页的七个固定小节

`product-steel.html` 是模板，其余三个产品页结构完全一致：

| 小节 | 内容 | 说明 |
| --- | --- | --- |
| 01 系统构成 | 子系统列表 | 一个产品族下的 3–4 个具体体系 |
| 02 选型参数 | 规格表 | 跨度 / 柱距 / 荷载 / 适用场景，设计院选型直接看这里 |
| 03 材料与规范 | 标准清单 | 引用的国标与国际标准，投标资格审查会看 |
| 04 性能与选项 | 可选配置 | 防腐等级、防火极限、连接方式等 |
| 05 适用场景 | 行业网格 | — |
| 06 **技术资料下载** | 样本 / 节点图 / BIM / 检测报告 / 安装手册 | **制造商站的核心**，目前全部是"待上传"状态 |
| 07 相关工程 | 案例引用 | 从工程业绩里挑 3 个 |

新增产品时，复制 `pages_product.py` 里 `P` 字典的任一项改内容即可（生成器见文末）。

## 设计说明

视觉参照国际工业制造商的做法，不是国内建站模板的路子：

- **近黑 + 暖白纸色 + 单一铁锈红**（`#15171a` / `#f6f4f1` / `#b23a1b`）
- **直角、无阴影、无渐变**，分隔一律用 1px 发丝线
- **左对齐非对称栅格**（12 栏），小标签在左侧留白栏
- **照片驱动**：全站没有装饰性插画，图形位都是等待替换的实拍图位
- **动效克制**：只有一次性淡入，没有数字滚动、没有视差
- 拉丁字体在前、中文字体兜底，中英混排时西文走无衬线 Grotesk

### 出口业务要特别注意

英文版里写了「可按 EN 1993 / EN 1090 / AISC 360 设计制造」。
**如果公司没有相应的 EN 1090 工厂生产控制认证，不要保留这句**，或改成
"可按……标准设计"并去掉制造。欧盟项目对 CE 标识和 FPC 证书查得很严，

## 配图

全站 **74 个图片位**，带斜纹底、左下角标注用途。搜 `data-slot` 定位全部。替换方式：

```html
<!-- 把这个 -->
<div class="fig fig--16x9" data-slot="产品首图位 — 建议 2400×1000"></div>
<!-- 换成 -->
<img src="assets/img/xxx.jpg" alt="……" width="1600" height="900" loading="lazy">
```

| 位置 | 比例 | 建议像素 |
| --- | --- | --- |
| 首页首屏 | 铺满 | 2400×1400，厂区航拍或主体吊装 |
| 产品页首图 | 21:9 | 2400×1000，该系统的实拍 |
| 产品索引卡 | 16:9 | 1600×900 |
| 全幅横条 | 21:9 | 2800×1200，制造车间 |
| 案例缩略图 | 4:3 | 1200×900 |

照片是这套设计的主角。拿到实拍图之前站点会明显偏空 —— 这是刻意的，
比用图库图或插画占位更诚实。

## 表单对接

联系页表单**只做前端校验，不发送任何数据**。逻辑在 `assets/js/main.js` 的 `form()`，
搜 `TODO(上线前)`。接后端时把提示那一行换成 `fetch()`，指向 Cloudflare Worker /
企业邮箱网关 / 企业微信机器人 / CRM。同时加验证码或频率限制。

提示文案通过 HTML 上的 `data-msg-invalid` / `data-msg-demo` 传入，中英文各自独立。

## 部署

**Cloudflare Pages**：构建命令留空，输出目录 `sites/jingong`。

```nginx
server {
    listen 80;
    server_name www.example.com;
    root /var/www/jingong;
    index index.html;
    error_page 404 /404.html;
    location ^~ /en/ { error_page 404 /en/404.html; }
    location ~* \.(css|js|svg)$ { expires 7d; }
}
```

## 维护说明

- **仓库里存的是成品 HTML**，可以直接手改，不需要任何工具链。代价是页头页脚重复在
  24 个文件里 —— 改导航或页脚时要么 24 个文件都改，要么用 `sed -i` 批量替换。
- **中英文是两套独立文件**，改了中文记得同步 `en/`，两边 DOM 结构必须一致，
  否则 hreflang 对不上。
- **配色与字号集中在 `assets/css/main.css` 顶部的 `:root`**。
- 图标是每页内联的 SVG sprite，只有三个：箭头、下拉、返回顶部。

## 已验证

- 响应式：24 个页面 × 360/390/768/1024 四档视口 = **96 项全部无横向溢出**
- 无障碍：跳转链接、`aria-expanded` 抽屉、键盘可操作、表单错误可读屏、

  Open Graph，首页带 Organization JSON-LD；sitemap 22 条 URL 含双语 alternate
- 打印样式：隐藏导航、页脚与筛选器
